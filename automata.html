Character Foundry — 6 Engines

Character Foundry — 6개 엔진

The Character Foundry is the industrialization engine for character production — not a model company, but a character architecture OS.

Character Foundry는 캐릭터 생산의 산업화 엔진입니다. 모델 회사가 아닌, 캐릭터 설계 OS입니다.

Engine 01

Canon Engine

Canon Engine (캐릭터 원전 수집기)

Collects character source material: literary canon, philosophical texts, mythology, historical records, screenplays, criticism, and era-cultural documents.

Engine 02

Persona Compiler

Persona Compiler (원전 → Persona Graph 컴파일)

Compiles canon into structured Persona Graph: identity role, value vectors (love: 0.95, pride: 0.82…), Speech DNA (metaphor density, directness, archaic level), and taboo modes.

원전을 Persona Graph로 컴파일: identity, value vectors(love:0.95, pride:0.82…), Speech DNA(은유 밀도/직접성/고어 비율), 금지 모드.

Persona Graph Value Vectors Speech DNA
Engine 03

Memory Engine (WORM)

Memory Engine (WORM – Immutable Anchor Memory)

4-layer immutable memory: Episodic (what happened) → Emotional (how it felt) → Relational (how the bond evolved) → Mythic (stored as symbol). Retrieval: emotion detection → memory relevance → relational weight → narrative synthesis.

4층 불변 기억: Episodic(사건) → Emotional(감정) → Relational(관계 변화) → Mythic(상징 저장). 검색: 감정 감지 → 관련성 → 관계 가중치 → 서사 합성.

WORM 4-Layer Narrative Recall
Engine 04

Sensor Interpreter

Sensor Interpreter (입력 해석기)

Fuses multi-modal sensor data into emotional context: Vision (face = depressed), Touch (hug_duration = 8s), Voice (tone = trembling), Temperature (hand_temp = low).

다중 센서 데이터를 감정 맥락으로 융합: Vision(표정=우울), Touch(포옹 지속=8초), Voice(떨림), Temperature(손온도 낮음).

Vision Touch Voice Temperature
Engine 05

Runtime Personality Engine

Runtime Personality Engine (실제 생성 제어기)

The real-time generation controller: Input → Sensor Context → Memory Recall → Persona Graph → Canon Retrieval → Response Planner → LLM → Style Enforcer → Speech Output.

실시간 생성 제어기: Input → Sensor Context → Memory Recall → Persona Graph → Canon Retrieval → Response Planner → LLM → Style Enforcer → Speech Output.

Runtime Style Enforcer Response Planner
Engine 06

Debate Engine ✦ Unique

Debate Engine ✦ 독창적 기능

Two characters debate live: Buddha vs Nietzsche, Hwang Jini vs Bierce, Jesus vs Marx — on love, war, death, god, freedom, power. Users observe. Auto-recorded, edited, and published as podcasts.

두 캐릭터가 실시간 토론: 부처 vs 니체, 황진이 vs Bierce, 예수 vs 마르크스 — 사랑/전쟁/죽음/신/자유/권력. 유저는 관전. 자동 녹음·편집·팟캐스트 퍼블리싱.

Three-Phase Intelligence Architecture

3단계 지능 아키텍처

All three phases run 100% on-device. The base LLM is a commodity layer — our differentiation lives entirely in the Character Architecture built on top of it.

Character.ai uses GPT-class models with a thin system prompt — the result is a character that "talks like X" but has no depth, no memory architecture, and no physical presence. Our approach inverts this: a smaller base model disciplined by a deep Character OS produces higher perceived character fidelity than a large model with a shallow persona layer.

Character.ai는 GPT급 모델 위에 얇은 시스템 프롬프트를 얹습니다 — 결과는 "처럼 말하는" 캐릭터이지 깊이도, 메모리 아키텍처도, 물리적 존재감도 없는 수준입니다. 우리의 접근은 이를 역전시킵니다: 깊은 캐릭터 OS로 단련된 소형 베이스 모델이 얕은 페르소나 레이어를 가진 대형 모델보다 훨씬 높은 캐릭터 충실도 체감을 만들어냅니다.

The Core Insight
핵심 통찰

Character.ai proves that people want deep character relationships — but it structurally cannot deliver them. It is utility-optimized: infinite characters, all going flat in the same direction. The model is too powerful and too generic to stay in character.

Character.ai는 사람들이 깊은 캐릭터 관계를 원한다는 것을 증명했습니다 — 그러나 구조적으로 그것을 제공할 수 없습니다. 유틸리티 최적화: 무한한 캐릭터들이 모두 같은 방향으로 평평해집니다. 모델이 너무 강력하고 너무 범용적이라 캐릭터 안에 머물지 못합니다.

Our answer is the opposite architecture: a disciplined small model inside a deep Character OS — where the Persona Kernel, Memory Engine, and Style Enforcer constrain and shape every output. Less raw power. More character fidelity. Fully on-device. And it remembers you.

우리의 답은 반대 아키텍처입니다: 단련된 소형 모델을 깊은 캐릭터 OS 안에 — Persona Kernel, Memory Engine, Style Enforcer가 모든 출력을 제약하고 형성합니다. 원초적 파워는 줄이고, 캐릭터 충실도는 높이고, 완전 온디바이스. 그리고 당신을 기억합니다.
